# 发布前手工回归清单（Windows）

执行建议：
- 测试环境：Windows 10/11 x64，普通用户权限。
- 记录项：每条勾选「通过/失败」、截图或日志片段、失败复现步骤。
- 最少执行两轮：
  - 开发模式：`APP_DISTRIBUTION_MODE=0`
  - 产品模式：`APP_DISTRIBUTION_MODE=1`

## 1. Windows 启动体验
- [ ] 双击 `start.bat` 可正常启动。
- [ ] 控制台无明显报错，能看到服务监听信息。
- [ ] 首次启动时依赖缺失场景有可理解提示（若触发自动安装，流程可完成）。

## 2. 首次启动体验
- [ ] 首次打开页面无需手工配置即可进入首页。
- [ ] 默认房间信息在页面可见（房间号、推荐分享链接/原因）。
- [ ] 页面核心区域无白屏、无 JS 报错。

## 3. 默认房间显示与分享链接
- [ ] 启动后默认房间号已生成并显示。
- [ ] 复制分享链接按钮可用，复制内容包含 `?room=XXXX`。
- [ ] 分享链接在新标签页打开后可进入目标房间。

## 4. 双端加入（双浏览器/双机）
- [ ] A 端创建/使用默认房间，B 端通过分享链接加入成功。
- [ ] 两端都能收到房间成员更新（`room_update` 对应表现）。
- [ ] 房间人数与成员名称显示一致。

## 5. 断线重连
- [ ] 在宽限期内断开再连，可恢复到原会话（同玩家身份）。
- [ ] 超过宽限期后重连，按设计失败或需重新加入（行为可解释）。

## 6. 房主退出与房间生命周期
- [ ] 房主主动离开后，房主身份转移给剩余玩家。
- [ ] 最后一个玩家离开后，房间被清理（再次进入时表现符合预期）。

## 7. libzt 不可用回退
- [ ] `online-preferred` 且 libzt 初始化失败时，服务仍可启动并回退本地模式。
- [ ] `online-required` 且 libzt 初始化失败时，服务显式失败退出。
- [ ] `local` 模式下不依赖 libzt 也可正常启动。

## 8. 自动打开浏览器
- [ ] `AUTO_OPEN_BROWSER=true` 时，ready 后自动打开一次浏览器。
- [ ] `AUTO_OPEN_BROWSER=false` 时，不会自动打开浏览器。
- [ ] 启动过程不会出现重复打开多个标签页。

## 9. 产品模式 / 开发模式日志
- [ ] 开发模式可看到调试日志（`[debug] ...`）。
- [ ] 产品模式日志更简洁，保留关键状态和错误，不刷屏调试细节。

## 10. 分发目录启动（便携运行时）
- [ ] `dist/mygame-win64/launch-product.bat` 可启动（目标机无需预装 Node）。
- [ ] `runtime/node.exe` 存在，缺失时有清晰错误提示。
- [ ] 分发目录关键资源存在：`app/public`、`app/build/Release/libztaddon.node`、`app/third_party/libzt/winx64/libzt.dll`。
